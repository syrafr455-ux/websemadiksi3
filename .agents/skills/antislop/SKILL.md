# antislop

> Anti Slop: Rules for AI Coding Agents

> Follow these rules whenever generating or building UI for a website, web app, or any interface.
> The goal: the design should feel **crafted by a designer**, not generated by AI.
> Before applying antislop, resolve its mode using "Two Usage Modes" below. By default, ask during or after. For a saved preference or explicit session choice, instead announce `antislop active: <mode> (<source>).` once, including whether the source is `global preference` or `session override`.

---

## Two Usage Modes

On the first antislop activation in each session, resolve the mode in this order:

1. **Explicit session instruction:** use `during` or `after` only when the user explicitly selects that antislop mode in this conversation.
2. **Global preference (only if no explicit session choice):** read `%APPDATA%\antislop\settings.json` on Windows or `~/.config/antislop/settings.json`.
3. **Ask if unresolved:** ask during or after.

- **Mode 1 (During):** follow the rules while generating. This prevents slop from the start and ends with the Delivery Gate. Use it when building new UI.
- **Mode 2 (After):** audit an already-finished project. Produce a numbered findings list, prioritize (Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Locks = LOW), fix approved items, and report.

## What This Is (and What It Isn't)

`antislop.md` is a **filter**, not a style guide. It stops AI coding agents from producing generic, recognizable "AI slop" UI, without falling into the opposite failure: a sterile, lifeless default.

- This document does **not** impose an aesthetic: no prescribed colors, fonts, layouts, or "house style".
- This document does **not** ban visual techniques (gradients, glassmorphism, badges, card grids). What it rejects is **technique without purpose**.
- This document does two things only:
  1. Holds every visual decision to a **purpose test**: what does this technique serve? Write the reason down.
  2. Holds the result to a **liveliness bar**: the output must be alive and specific, not just "clean".

## The Craftsmanship Standard

### C-1 — Intentionality
Every visual and copy decision has a reason you can articulate. If the only reason is "it's the AI default", revisit the decision.

### C-2 — Functional Completeness
Every interactive element works, or it does not exist. A button or card that cannot do anything is a defect, not decoration.

### C-3 — Content-Driven Composition
Every section exists because the product's content needs it, not because every AI landing page has one. Remove sections that only fill a template.

### C-4 — Resilience
The UI holds up in every state (empty, loading, error), every theme you ship, every breakpoint, and keyboard-only use.

### C-5 — Evidence Over Claims
Anything presented as fact (testimonials, statistics, security claims) is real and verifiable, or it is not shown at all.

## Core Rules Summary

- **R-01 (Palette & Gradients)**: Do not use generic AI blue-to-purple, blue-to-cyan, or rainbow gradients. Color palettes must come from `DESIGN.md` or brand identity.
- **R-02 (AI Buzzwords)**: No empty buzzwords (*unlock, empower, elevate, seamless, robust, game-changer, next-gen*).
- **R-03 (Mobile Reflow)**: Mobile layout must reflow with intention, not just shrink desktop.
- **R-05 (Layout Variety)**: Do not use copy-paste card grids or forced 3-step sections.
- **R-07 (Backgrounds)**: No gratuitous dot grids, blueprint lines, or random blurred floating blobs.
- **R-10 (Glassmorphism)**: Max 1-2 elements if purposeful; never frosted glass on everything.
- **R-11 (Border Radius)**: Do not make every single element pill-shaped (`rounded-full`). Use deliberate scale.
- **R-12 (Shadows)**: No fuzzy floating shadows on every element. Elements sit flat; shadow indicates true elevation.
- **R-13 (Glow)**: No neon glowing borders, cards, or buttons everywhere.
- **R-17 & R-18 (Authentic Data)**: Never invent fake stats, fake ratings, or fake testimonials.
- **R-21 (Theme)**: Dark mode is an intentional choice, not a tech default.
- **R-25 (Contrast)**: Meet WCAG AA minimums (4.5:1 normal text, 3:1 large text).
- **R-36 (Honest Copy)**: No significance inflation (*"revolutionizing", "ushering in a new era"*).
- **R-38 (Authentic Visuals)**: No fake interactive mockups or foreign stock placeholders pretending to be the product.
